System

Operations

This page is for the person who runs scriptaWorlds: what has to be installed, how the server is started and configured, how the environment is verified before spending any model budget, what a restart does to work in progress, and how to read the failures an operator is likely to see.

Requirements

Two runtime requirements and one optional one are recorded in dependencies.md. Node.js 20 or later runs the server, the check script and both skill scripts; the repository was developed and verified on Node.js 24. The omp command (Oh My Pi, 18.2 or later) is the coding agent that writes every chapter and every edition; the server probes it with --version at startup and refuses to listen when the probe fails. A system serif TrueType font is required by the print renderer for any edition format, because the renderer resolves the font before it decides what to write, and the renderer reports the missing font instead of producing a broken file. One further tool is needed by the maintenance steps and by nothing else: pdftotext (from Poppler) reads the printed book when the data files are rebuilt from it — npm run library for the library of start templates and npm run table for the table of ideas. Both stop with a clear message when the tool is absent. The server, the check script and both skill scripts never call it, and the generated data files are committed, so a checkout runs without it.

The authentication and model access of the agent belong to the agent itself. The server does not read credentials, does not call a model API, and does not pass any token to the child process beyond the environment it inherits.

Starting the server

npm run check      # verify the environment and the whole technology chain without using the agent
npm run server     # start the API and the reader interface

The server listens on HOST and PORT, creates the universes/ folder when it does not exist, recovers the turns of every universe, refreshes the links to the product skills inside each universe, and prints the loopback address, every reachable IPv4 address of the machine, the agent it found and the effective concurrency limit. Network addresses are printed so that a reader can open the book on a phone on the same network. SIGINT and SIGTERM stop the intake of new turns first, then signal the running agent processes and wait for them to be gone — a bounded SIGTERM, then SIGKILL — and only then close the listener and release the store lock, so a second server can never start writing while a child of the first one is still alive. A second signal during that shutdown is ignored rather than releasing ownership early, and the turns that were still queued stay on disk and resume at the next start.

Because the runtime has no npm dependencies, there is no install step and no build step. Starting the server is running one Node.js file; the browser interface is served from public/ as it lies on disk, and the table of ideas and the library are read from data/ and library/ as they are committed.

Before it touches the store, the process takes the store lock in universes/.server.lock, so only one server owns a store. A second instance on the same folder prints one line on standard error and exits with status 1 without listening:

[start] another scriptaWorlds server is already running (pid 4812, since 2026-09-21T19:04:11.000Z) and owns /srv/scriptaWorlds/universes; stop it before starting a second one

The message names the process that holds the store and the moment it started, so the owner can be stopped deliberately. A lock left behind by a process that is gone — a killed server or a machine that was shut down — is recognised as stale as soon as the recorded process identifier is no longer alive, and the new instance takes it over; the lock is removed when the server stops with SIGINT or SIGTERM, and only after its running turns are gone. Starting two servers is not a way to serve one store twice: each of them would treat the turns of the other as interrupted, which is exactly what the lock prevents. Two independent books on one machine are two checkouts with two universes/ folders.

Configuration

Configuration is entirely through the environment. Values are read once at startup, so a change requires a restart.

Variable Default Effect
HOST 0.0.0.0 The address the server binds. The default accepts connections from the local network; set a loopback address to keep an instance private.
PORT 8787 The listening port. A non-positive or non-numeric value falls back to the default.
OMP_BIN omp The agent binary. Use it when the agent is installed outside PATH; the value is what the startup probe and every turn use.
SCRIPTAS_MODEL deepseek/deepseek-v4-flash The model used for every turn and recorded in each universe and turn.
MAX_CONCURRENT_JOBS 0 The global limit on turns running at the same time. 0 or an unset value means unlimited; each universe still runs at most one turn at a time.
CHAPTER_TIMEOUT_MS 1200000 The deadline of a chapter or rewrite turn, in milliseconds. It is also passed to the agent as its own maximum run time.
EXPORT_TIMEOUT_MS 1200000 The deadline of an export turn, in milliseconds.
ASSESSMENT_WORKSPACE assessments/ Where the separate design and review phases keep their frozen packets and published results. It is deliberately outside universes/: a phase never writes into a book, so a report can never roll back a chapter. Point it at another directory to keep reviews on a different disk.
ASSESSMENT_TIMEOUT_MS 300000 The deadline of one review run, in milliseconds. A run that passes it is terminated and recorded as an error with the reason.
ASSESSMENT_MODE generic Who produces the semantic observations of a review, and the default for the mode field of an assessment request. generic makes the server run the annotation stage: one OMP_BIN call in the run workspace with the model from SCRIPTAS_MODEL per metrics review, plus a single repair call when the answer is rejected. deterministic asks nobody, leaves those results unavailable with their reason and keeps a deployment free of model calls. Any other value falls back to generic.
IMPORT_MAX_BYTES 67108864 The largest book the server accepts as an upload, in bytes, enforced while the file is still arriving: a body over it is refused during the transfer with 413 IMPORT_TOO_LARGE instead of after it has been stored. How much of a book one import turn carries is not configured here: the import skill publishes its turn limits in skills/scripta-import/schema/import.v1.json.
CHAPTER_MIN_WORDS 900 The lower bound of the word band stated in the prompt and used to warn about a short chapter.
CHAPTER_MAX_WORDS 2400 The upper bound of the word band stated in the prompt and used to warn about a long chapter.

The word band and the concurrency limit are reported by GET /api/config, so a client can present them without being configured itself.

The environment check

npm run check runs scripts/check.mjs, which proves the whole technology chain without spending model budget. It verifies the Node.js version, probes the agent binary, asserts that both skill manifests exist, creates temporary universes, checks the default language and the language change, exercises the fundamental law and language validation paths, asserts that skill links are installed inside a universe, writes a chapter with diacritics and reads it back through the store, closes and reopens a universe, runs the narrative validator and parses its JSON report, runs the print renderer and requires a positive page count, lists universes, and finally reproduces a restart and the store's failure paths: a queued turn stays on disk, a running turn becomes interrupted and the canon is rolled back while the partial chapter disappears, a missing or tampered snapshot leaves that turn recovery-required and blocks the book for writing, a restore puts back the exact accepted file set twice in a row, a chapter being written stays hidden from readers until the commit, a rewrite whose target changed while it waited behind another turn fails as a stale request without touching the book, a failing archive stops a deletion, a real agent process is signalled and waited for during shutdown, and a rendered edition is accepted while a truncated one is refused. It then runs the separate-phase half of the product with no model budget: it freezes a synthetic accepted book as an assessment-input.v2 packet in the workspace layout, runs the continuity review and the metrics report over that packet, requires the five report views and all twelve metrics, asserts that neither phase changed a byte of the packet, and tampers with one chapter to prove that both skills refuse the packet with the same code and publish nothing. It then exercises the orchestration around those phases: a capture is refused while the book is being written, both phases publish into the external workspace while the store stays byte-identical, an identical request is deduplicated, a rewrite makes an older result historical, a restart keeps a queued run and interrupts a running one, an arc-completion event is versioned and deduplicated, and an approval records its decision, refuses a stale proposal and is never rewritten. It also asserts the data and the paths this release depends on: the one hundred and eighty cells of the table of ideas with the systematic symbol of every cell and the page of the book behind each of them, the resolution of ingredients and the composition of the law, together with the assertion that neither the law nor the ingredient lines nor the AGENTS.md of a universe carries a two-letter symbol instead of the sentence, the mapping of the creation request body in which premise wins over opening, the fact that a template keeps its own cells while the reader may add ingredients on top, the library index against the folders on disk — with the indications and the source text of a night template — and the universe composed from a template, the short name adopted from the hand-off file and the long line that is refused, the store lock refusing a live owner and taking over a stale one, and the fact that importing the server module starts no server and takes no lock. It exits with status 0 only when every check passed, and it always removes the universes it created.

Run it before starting a server on a new machine, after installing or upgrading the agent, and after changing anything that touches the universe file contract. It is the fastest way to distinguish an environment problem from a story problem.

Rebuilding the library and the table

The two data sources a reader explores are generated from the printed book, and the generated files are committed, so nothing has to be rebuilt to run the product. The steps exist for the case where the book changes or where the generation itself is being worked on:

npm run library              # rebuild library/index.json and every library/<slug>/
npm run table                # rebuild data/periodic-table.json from the book
npm run library -- --check   # compare the library with the index, the folders and the book; write nothing
npm run table -- --check     # compare the table with the book; write nothing

All four commands read vision/periodic_table.pdf with the system tool pdftotext, which is why a machine that only runs the server does not need it. npm run table writes data/periodic-table.json — the twelve families with the cells that belong to them, the fifteen operators and the one hundred and eighty cells, each with its name, mechanism, prompt line, ingredient sentence, landmark and prose sections — and it refuses to write anything when the book does not parse cleanly, printing the problems it found instead of a half-built table; its --check mode compares the committed file with the book on the cell count and on the name, operator, gist and prompt of every cell. npm run library writes library/index.json plus one folder per template with a template.json, spends no agent budget, and fails the same way when pdftotext is missing or the book cannot be read; its --check mode prints one line per problem and exits with a nonzero status. The empty template is not generated: it is written by hand under library/empty/, and a rebuild re-serializes it and keeps it first in the index.

A rebuild is a content change rather than a runtime change, and the process keeps what it read: src/library.mjs caches the index and every template it has opened for the life of the server, and src/periodic.mjs does the same with the table of ideas. A rebuilt library is therefore visible after a server restart, not in a running one, and a page reload alone does not change it. The index and the folders have to stay consistent, which is what --check is for; an index entry whose folder is gone answers 404 UNKNOWN_TEMPLATE when that template is opened, and the check reports it before a reader meets it.

Updating the interface while it is open

The reader interface is served from public/ as it lies on disk, with Cache-Control: no-cache, so a reload revalidates every module and picks up the files as they are now; no restart, build or cache invalidation step is needed after editing a file of the interface. A tab that was already open, however, holds the modules it loaded; when the interface is replaced under it — an updated build, or a file renamed or removed while the tab stayed open — the next dynamic import fails and the page would otherwise sit there dead.

That case is handled inside the page itself. The shell of public/index.html installs a small error listener before the application module loads, and it answers with one line and a reload control instead of an empty screen:

The interface was updated while this page was open.   [ Reload ]

The same banner reports The interface could not start. when the bootstrap fails for another reason, and the Reload control performs a plain reload, which fetches the current files. The banner never replaces the book content that is already rendered: it is a line at the bottom of the page, and the reader can keep reading until they reload.

Checking a review against a real evaluator

The environment check proves the review pipeline with a stand-in evaluator and spends no model budget. One bounded review against the real one is nevertheless worth running after a change to the prompt, to the reader of its answers, or to the model: it is the only way to see what the configured evaluator actually returns.

Start the server against a copy of the tree and a book with one chapter, then ask for a measurements review whose observations come from the evaluator, and watch the run rather than the request:

POST /api/universes/<id>/assessments  {"phase":"metrics","mode":"generic","force":true}
GET  /api/universes/<id>/assessments/<runId>

The request answers at once with the run queued or already running, because the evaluator is called inside the run. What the record then shows is the evidence: annotation_attempts with one entry per call, each with its exit code, its answer length, how long it took and the validation errors it produced, then the published files and packet_intact. A first attempt that a repair call corrects is a normal outcome, not a failure — the repair prompt names the fields that failed. A run that ends with annotation stage: in its error published nothing and can be retried; a retry reuses the document it already accepted.

Two calls at most belong to one review, so a smoke like this costs a bounded amount of model time. Give it a book of one chapter in a throwaway copy of the tree, never the books the team reads.

Restarts, interruptions and recovery

A restart is safe by design. Turns recorded as queued are resumed automatically in turn order with their original requests, and turns recorded as running become interrupted: the canon, thread and atlas files are restored from the snapshot taken before that turn, the partial chapter and offer files are removed, and the turn stays visible with a retry action in the interface or through the retry route. Nothing else is lost; the reading position is in the browser, and the rest is on disk.

An interrupted or failed turn is the operator's cue, not the reader's problem: check the agent log recorded with the turn for the tools it used and the tail of its raw output, verify that the agent still works with npm run check, and retry. Because the canon snapshot of every chapter is kept on disk, an interrupted turn never leaves a half-written chapter in the book, and because a retry reuses the same turn number, the numbering of the book has no holes.

Access and exposure

The API has no accounts. Anyone who can reach the address can read every universe, create one, close it, rewrite a chapter and generate editions, and the server has no CORS configuration to relax. An operator who needs a private instance sets HOST to a loopback address or places a reverse proxy in front of the server. Two proxy behaviours matter: buffering delays or breaks the live text of the event stream, and an idle connection timeout can close a stream during a long chapter. In both cases the reader interface degrades to slower progress instead of failing, because it falls back to polling the job route.

Editions and fonts

An export turn asks the agent to write the editorial metadata and then run the print renderer. The renderer looks for a serif TrueType font in a fixed order of system locations, requires that the chosen family covers every character of the book, and fails with MISSING_FONT when no family covers at least the Latin set plus the Romanian diacritics. Install a serif font package for the platform, or point the renderer at a folder of .ttf files with its own font option; OpenType CFF fonts and font collections are ignored by the search.

Failure reference

Code Meaning and remedy
OMP_MISSING The agent binary could not be started. Install the agent, ensure it is in PATH, or set OMP_BIN. The server exits at startup with this code and does not serve a universe it cannot continue.
AGENT_FAILED The agent did not start, exited with a nonzero status, or exceeded its deadline. The last accepted book has already been restored from the snapshot; inspect the turn's agent log, fix the cause and retry the turn.
NO_CHAPTER The agent finished without writing the expected chapter file. Retry, and check the skills are present in the universe folder.
DUPLICATE_CHAPTER The turn left more than one chapter file for the same chapter number, usually a rewrite that changed the slug without removing the old file. The failure path removes the extra files and restores the accepted chapter; retry after checking the agent log.
INVALID_CHAPTER The chapter failed the skill's structural validator, so it was not accepted: a missing or malformed plan, offer, canon, threads or atlas file. The message names the validator errors, and the accepted book is restored; retry after the cause is fixed.
NO_ANCESTRY A rewrite was requested for a chapter whose pre-chapter state is not recorded, so the book cannot be rewound safely. Reconstruct the state that preceded the chapter — canon, threads and atlas — or rewrite the last chapter instead.
STALE_REQUEST A queued rewrite reached the front of its queue and the book no longer matches the request: the target changed, or a later chapter appeared that the request never authorised dropping. Nothing was rewritten; read the chapter again and ask for the rewrite again.
RECOVERY_REQUIRED A turn failed or was interrupted and the snapshot taken before it is missing or unusable, so the accepted state of that book is unknown. Every new turn and every retry is refused until the accepted version is established by hand; the reason names the unusable snapshot.
SHUTTING_DOWN The server stopped accepting new turns because SIGINT or SIGTERM arrived. Wait for the process to end and start it again; queued turns are on disk and resume.
UNSTABLE_VERSION A review was requested while a turn of that book was queued or running, so the packet would not be an accepted version. Wait for the turn, or capture from the snapshot of a finished turn.
MISSING_FILE A review could not freeze the accepted version because a file the packet must contain is absent (a state file, or a chapter the manifest expects). The book is incomplete rather than unstable; establish the missing file first.
BAD_STATUS The status asked for is not open or closed.
NO_PROFILE The metrics phase was requested without an evaluation profile. Supply one (profile.v1), because the measurements depend on the scope and the aggregation it declares.
ANNOTATION_FAILED The annotation stage of a review asked the configured evaluator for observations and received no document it could accept, so the run was recorded as an error with the reason the evaluator gave, instead of reporting an invented judgement. The run record names the attempts, their exit codes and the validation errors; check that the agent binary and the model work, retry the run, bring an annotations document yourself, or set ASSESSMENT_MODE=deterministic to run the review without a model.
NOT_CANCELLABLE A review that already settled was asked to cancel. Read its result, or start a new run over the same packet.
BAD_ARC An arc-completion event carried an identifier that is not lowercase letters, digits and hyphens. The identifier is what deduplicates the assessments of that arc.
NO_EXPORT An export turn produced no .pdf or .docx file for a requested format. Usually MISSING_FONT or a renderer usage error; read the agent log for the renderer's JSON line.
INVALID_EXPORT The edition file the agent left is empty or is not a valid PDF or DOCX document, so it is not reported as a produced edition. Read the renderer's JSON line in the agent log; the file is usually a truncated run or a failed write.
NO_TABLE data/periodic-table.json is missing or unreadable, so no universe can be composed and GET /api/table cannot answer. Restore the file from the repository; the table is a committed data contract, not a generated artifact of the running server.
NO_LIBRARY library/index.json is missing or unreadable, so the Library tab cannot list a starting point while the rest of the product still works. Restore library/ from the repository, or regenerate it with npm run library on a machine that has pdftotext.
CLOSED A chapter turn or a rewrite was requested for a closed universe. Reopen the universe first; editions are still allowed while it is closed.
LANGUAGE_LOCKED A language change was requested for a book that already has chapters. The accepted prose is written in the current language, so the language is fixed; start a new universe to write in another language.
NOT_RETRYABLE The turn is not interrupted or failed, so retrying it would duplicate work. Read the universe detail instead.
NOT_FOUND on a job route The job belonged to an earlier server process. Jobs are in-memory handles; the durable record of that work is in the universe's turn list.
TOO_LARGE or BAD_JSON The request body exceeded 512 KiB or was not a JSON object. Check the client that produced it.

The full route list, the error envelope and the durable queue rules are specified in DS005-http-api and DS003-main-behavior. The exact file formats an operator may need to inspect by hand are in DS004-universe-storage and docs/contracts.md.
